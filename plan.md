# Название проекта: Логистический хаб

## Цель проекта
Реализация работы логистического хаба от приёма товаров от поставщиков до формирования и отправления посылок покупателям.

## План работы хаба
Приём товара → Хранение товара → Получение заказа → Формирование посылки → Хранение посылки → Погрузка курьерской машины → Отправка курьерской машины

## Роли

### Роль: admin (Администратор)
Главная задача: настройка системы и управление справочниками.
Пункты меню:
- Управление складом:
  - Добавить/изменить склад (площадь, адрес)
  - Добавить/изменить зону (название, код, лимиты)
  - Добавить/изменить стеллаж
  - Добавить/изменить полку (включая смену статуса: active/blocked/maintenance)
- Управление автопарком:
  - Добавить/изменить курьерскую машину
  - Назначить/снять районы обслуживания для машины
- Управление справочниками:
  - Добавить/изменить район доставки
  - Добавить/изменить поставщика
  - Добавить/изменить товар
- Управление пользователями:
  - Создать пользователя (логин, пароль, роль)
  - Удалить/заблокировать пользователя
- Просмотр журнала аудита (фильтр по дате, пользователю или типу операции)
- Просмотр статистики:
  - Заполненность склада (по зонам и типам товаров)
  - Динамика поставок и отгрузок (за выбранный период)
  - Эффективность работы курьерских машин
  - Активность сотрудников (количество выполненных операций)

### Роль: manager (Менеджер)
Главная задача: операционное управление потоками, контроль и симуляция внешних событий.
Пункты меню:
- Симуляция внешних событий (Генератор):
  - Сгенерировать 1 случайный заказ
  - Сгенерировать пакет заказов (ввести число N)
  - Сгенерировать 1 случайную поставку
  - Сгенерировать пакет поставок (ввести число N)
- Сводка (Дашборд):
  - Показать текущую заполненность склада (по зонам)
  - Показать статусы машин (доступно, в рейсе)
  - Показать количество заказов и посылок по статусам
- Управление поставками (Обработка):
  - Просмотреть список поставок со статусом pending
  - Подтвердить (accepted) или отклонить (rejected) поставку
- Управление посылками и отгрузкой:
  - Просмотреть список собранных посылок (assembled), готовых к отправке
  - Сгруппировать посылки для машины (выбрать машину и назначить ей посылки)
  - Загрузить машину (перевод посылок в loaded)
  - Отправить машину в рейс (перевод машины в on_route)
  - Завершить рейс машины (симуляция возврата)
- Ручное перемещение товара:
  - Переложить товар с одной полки на другую (с указанием причины)

### Роль: receiver (Приёмщик)
Главная задача: приём товара от поставщиков и размещение на складе.
Пункты меню:
- Выбор поставки для приёмки:
   - Просмотреть список поставок со статусом pending
   - Выбрать поставку по ID
   - Просмотреть состав поставки (товар, ожидаемое количество)

- Приёмка товара:
   - Выбрать товар из состава поставки
   - Ввести фактическое количество
   - Система автоматически размещает товар на полках (Алгоритм 1)
   - При расхождении фактического и ожидаемого количества — предупреждение (не блокирует)
   - Защита: товар обязан входить в состав поставки (жёсткий контроль)

- Завершение поставки:
   - Подтвердить окончание приёмки (перевод поставки в статус accepted)
   - Смена поставки заблокирована, пока текущая не завершена

### Роль: assembler (Сборщик)
Главная задача: сборка товаров из посылок по поступающим заказам.
Пункты меню:
- Создать посылку из заказа:
   - Просмотреть список заказов со статусом processing
   - Выбрать заказ по ID
   - Система автоматически определяет тип посылки на основе товаров:
     * только regular → standard
     * есть perishable → express (приоритет)
     * есть oversized → oversized 
- Выбрать посылку для сборки:
   - Просмотреть список посылок со статусом new, отсортированный по приоритету
   - Выбрать посылку по ID (защита: нельзя выбрать, если уже есть активная)
- Просмотреть состав активной посылки:
   - Список товаров и их расположение на полках
   - Защита: доступна только при выбранной посылке
- Собрать активную посылку:
   - Вызов автоматического алгоритма сборки (Алгоритм 2)
   - При успехе: посылка → assembled, заказ → assembled, current_parcel_id сбрасывается
   - При нехватке товара: заказ → canceled, посылка остаётся в new
   - Защита: доступна только при выбранной посылке
- Выйти в главное меню (защита: нельзя выйти при активной посылке)
- Выйти из приложения (защита: нельзя выйти при активной посылке)

## Алгоритмы

### Алгоритм 1: Выбор полки при приёмке
**Входные данные**: товар (тип, вес единицы, объём единицы), количество
**Шаги**:
1. Определить тип товара - выбрать соответствующую зону:
    regular - "Обычная"
    perishable - "Холодная"
    oversized - "Крупногабаритная"
2. Найти все активные полки в этой зоне (status = 'active')
3. Отфильтровать полки, где есть свободное место:
    current_weight + (вес_единицы × количество) <= max_weight
    current_volume + (объём_единицы × количество) <= max_volume
    Если подходящие полки найдены:
    Отсортировать по заполненности: сначала по весу (current_weight / max_weight), при равенстве - по объёму (current_volume / max_volume)
4. Поместить товар на первую полку из списка
    Если товар не влезает полностью - поместить часть, остаток перенести на следующую полку
    Если подходящих полок нет - уведомить менеджера, товар остаётся в зоне ожидания (буфер). Администратор должен будет создать новую полку/стеллаж/зону.
**Выходные данные**: ID полки (или нескольких полок), количество размещённого товара

### Алгоритм 2: Сборка посылки
**Входные данные**: посылка (список товаров и количества)
**Шаги**:
Для каждого товара в посылке:
1. Найти все полки, где есть этот товар
    Если товар perishable - отсортировать полки по принципу FIFO (сначала товар, который лежит дольше всего — по полю received_at)
    Иначе - отсортировать по заполненности (сначала самые заполненные полки)
2. Списать товар с полок:
    Начать с первой полки в списке
    Если на полке меньше, чем нужно - взять всё, перейти к следующей полке
    Если на полке достаточно - взять нужное количество, остановиться
    Если товара не хватает на всём складе → отменить посылку полностью, уведомить менеджера.
3. Обновить данные:
    Уменьшить quantity в shelf_products
    Уменьшить current_weight и current_volume на полке, стеллаже, зоне
    Уменьшить quantity_in_stock в products
4. Рассчитать фактический вес и объём посылки:
    weight = SUM(вес_единицы × количество) для всех товаров
    volume = SUM(объём_единицы × количество) для всех товаров
5. Изменить статус посылки на assembled
**Выходные данные**: обновлённые остатки на полках, вес и объём посылки

### Алгоритм 3: Погрузка машины
**Входные данные**: машина (лимиты по весу, объёму, количеству посылок), список готовых посылок (status = 'assembled')
**Шаги**:
1. Получить список посылок, готовых к отправке
2. Отфильтровать посылки по районам обслуживания машины:
    Район посылки должен быть в списке vehicle_districts для этой машины
    Отсортировать посылки по приоритету:
    urgent - high - normal - low
    Внутри одного приоритета → по сроку годности (сначала скоропортящиеся)
3. Загружать посылки в машину по одной:
    Проверить лимиты:
    current_parcels + 1 <= max_parcels
    current_weight + посылка.weight <= max_weight
    current_volume + посылка.volume <= max_volume
    Если все лимиты соблюдены → загрузить посылку
    Если хотя бы один лимит превышен - пропустить посылку, оставить в очереди для следующей машины
4. Обновить данные:
    У посылки: status = 'loaded', vehicle_id = ID машины
    У машины: увеличить current_weight, current_volume, current_parcels
    Изменить статус машины на loading
**Выходные данные**: список загруженных посылок, обновлённые параметры машины
